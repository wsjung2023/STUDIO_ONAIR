# Production Avatar Creator 통합 설계

- 상태: 사용자 승인 완료
- 승인일: 2026-07-24
- 대상 제품: Creator Studio
- 대상 플랫폼: Windows, macOS, Android
- 대상 표현: 2D Inochi2D, 3D VRM 1.0 또는 glTF 2.0 기반 비휴머노이드 리그

## 1. 목표

Creator Studio 안에 상업용 방송과 녹화에 실제로 사용할 수 있는 고품질 아바타
크리에이터를 탑재한다. 사용자는 완성형 캐릭터를 고르는 데 그치지 않고 사람,
케모미미, 수인, 마스코트, 완전한 동물 캐릭터를 세부적으로 커스터마이징할 수
있어야 한다.

2D와 3D는 하나의 편집 경험과 공통 캐릭터 설정을 공유한다. 최종 미리보기,
Studio 녹화, 외부 방송 출력에는 정적 이미지나 별도 데모 렌더러가 아니라 같은
실제 런타임을 사용한다.

이 기능은 MVP나 시각 목업이 아니다. 다음 전체 흐름이 실제 제품 코드로 동작해야
완료다.

`캐릭터 생성 → 세부 편집 → 웹캠 보정 → 실시간 추적 → 저장·재실행 → 녹화·방송 → 허용된 모델 내보내기`

## 2. 제품 원칙

### 2.1 품질 원칙

- 기본 미술 방향은 2D 고급 애니풍과 3D 셀 셰이딩 애니풍이다.
- 모든 프리셋은 편집 가능한 시작점이다. 고정 캐릭터 선택 화면으로 끝내지 않는다.
- 중앙 미리보기는 녹화와 방송에 쓰이는 실제 렌더 파이프라인을 사용한다.
- 정적 PNG, 테스트 패턴, 연결되지 않은 버튼, 한 종류뿐인 샘플은 완료가 아니다.
- 기능을 단계별로 개발하더라도 각 단계는 실제 자산과 실제 런타임으로 검증한다.
- 2D와 3D를 똑같아 보이게 자동 변환한다고 약속하지 않는다. 공통 의미 설정을
  공유하고 각 엔진의 장점을 살린 별도 고품질 결과를 만든다.

### 2.2 상업 사용 원칙

- 기본 제공 자산은 자체 제작하거나 계약으로 상업 이용 권리를 확보한 자산만 쓴다.
- 방송·녹화 수익화, 앱 번들 재배포, 변형, 파생 캐릭터, 원본 모델 내보내기,
  원본 파츠 재배포 권리를 서로 다른 권리로 관리한다.
- 출처 불명, 비상업 전용, 재배포 조건 불명 자산은 기본 패키지에 포함하지 않는다.
- 외부 모델의 권리를 Creator Studio가 법적으로 보증한다고 표현하지 않는다.
- 내보내기 권리가 없는 기본 자산도 허용 범위 안에서는 Creator Studio와 방송
  출력에서 상업적으로 쓸 수 있다.

Inochi2D SDK의 BSD-2-Clause와 모델 자산의 개별 권리는 분리해서 판단한다.
VRM 파일에 기록된 이용 조건도 모델별로 읽어야 한다. Live2D SDK는 임의 모델을
불러오는 확장형 애플리케이션에 별도 계약이 필요하므로 이 설계의 기본 엔진으로
추가하지 않는다.

공식 참고:

- Inochi2D: <https://github.com/Inochi2D/inochi2d>
- VRM 1.0 라이선스: <https://vrm.dev/en/licenses/1.0/>
- Live2D 확장형 애플리케이션: <https://www.live2d.com/en/sdk/license/expandable/>

## 3. 범위

### 3.1 포함

- 공통 `AvatarSpec`과 자산 카탈로그
- 2D Inochi2D 모듈형 캐릭터 컴파일 및 렌더링
- 휴머노이드 3D VRM 1.0과 비휴머노이드 glTF 2.0 로딩, 모듈 조합,
  셀 셰이딩 렌더링
- 사람, 케모미미, 이족 수인, 마스코트, 사족 동물 리그
- 얼굴, 시선, 입, 머리, 상체, 양손 추적
- 오디오 립싱크와 추적 실패 시 자연스러운 대기 모션
- 데스크톱과 Android의 동일 모델·설정 호환
- Creator Studio 녹화와 OBS용 출력
- 권리가 허용된 자산만 `.inx`, `.vrm` 또는 비휴머노이드 `.glb`로 내보내기
- 자산 서명, 해시, 버전, 출처, 라이선스 증빙
- 자동 저장, 복구, 실제 기기 성능 및 장시간 안정성 검증

### 3.2 제외

- Inochi Creator나 Blender를 대체하는 전체 리깅·모델링 도구
- 사용자가 처음부터 메시를 조각하거나 2D 원화를 그리는 기능
- 2D 모델을 3D 모델로, 또는 3D 모델을 2D 모델로 완전 자동 변환하는 기능
- 권리가 확인되지 않은 모델을 `상업 사용 확인됨`으로 표시하는 기능
- 클라우드 계정이나 외부 생성 서비스가 없으면 작동하지 않는 구조
- 초기 범위의 사용자 간 자산 마켓플레이스

## 4. 핵심 아키텍처

### 4.1 전체 흐름

```text
Avatar Workspace
    │
    ▼
AvatarEditorController
    │
    ├── AvatarCatalog ── AssetPackageValidator ── LicenseResolver
    │
    └── AvatarSpec
            │
            ▼
       AvatarComposer
        │          │
        ▼          ▼
2D AvatarCompiler  3D AvatarCompiler
        │          │
        ▼          ▼
Inochi2D runtime   VRM runtime
        └─────┬────┘
              ▼
       AvatarRenderPipeline
              │
      ┌───────┼────────┐
      ▼       ▼        ▼
   Preview  Recorder  Broadcast output
```

트래킹 경로는 렌더 경로와 분리한다.

```text
Camera + Microphone
        │
        ▼
Tracking Providers
        │
        ▼
AvatarMotionFrame
        │
        ▼
Rig Retargeter
        │
        ├── Inochi2D parameters
        └── 3D bones and expressions
```

### 4.2 모듈 책임

| 모듈 | 책임 |
|---|---|
| `AvatarSpec` | 사용자의 캐릭터 선택, 수치, 색상, 소재, 표현, 물리 설정을 엔진 독립적으로 저장 |
| `AvatarCatalog` | 설치된 파츠와 프리셋 검색, 호환성, 버전, 권리 상태 제공 |
| `AssetPackageValidator` | 패키지 스키마, 서명, 해시, 의존성, 파일 경로와 성능 예산 검증 |
| `LicenseResolver` | 조합된 아바타의 방송·편집·내보내기·재배포 권리를 최소 허용 범위로 계산 |
| `AvatarComposer` | 슬롯 충돌과 리그 호환성을 검사하고 엔진별 컴파일 입력 생성 |
| `2D AvatarCompiler` | 사전 리깅된 2D 모듈을 아틀라스, 레이어, 마스크, 파라미터 매핑과 함께 컴파일 |
| `3D AvatarCompiler` | 메시, 본, 의상, 모프, 소재, LOD를 VRM 또는 비휴머노이드 glTF 런타임 입력으로 컴파일 |
| `AvatarMotionFrame` | 얼굴, 포즈, 손, 오디오 특성을 공급자 독립 형태로 운반 |
| `Rig Retargeter` | 공통 모션을 사람형·수인형·사족형 등 대상 리그의 실제 파라미터로 변환 |
| `AvatarRenderPipeline` | 편집기, 녹화기, 방송 출력에 동일한 RGBA 프레임 제공 |
| `AvatarEditorController` | QML에 편집 명령과 읽기 전용 상태를 노출하고 자동 저장·실행 취소 관리 |

각 모듈은 내부 구현을 읽지 않아도 입력, 출력, 실패 조건을 알 수 있는 인터페이스를
가져야 한다. `cs_avatar`의 순수 도메인 경계에는 Qt, MediaPipe, Inochi2D, VRM
구현 타입을 노출하지 않는다.

## 5. 공통 캐릭터 데이터

### 5.1 `AvatarSpec`

`AvatarSpec`은 다음 정보를 저장한다.

| 영역 | 필드 |
|---|---|
| 식별 | `schemaVersion`, `avatarId`, `displayName`, `createdAt`, `modifiedAt` |
| 분류 | `rigFamily`, `speciesFamily`, `styleTheme`, `preferredRepresentation` |
| 형태 | `bodyMorphs`, `faceMorphs`, `animalMorphs` |
| 파츠 | 슬롯별 `AssetRef(assetId, version, variantId)` |
| 색상 | 재사용 가능한 팔레트와 파츠별 색상 채널 오버라이드 |
| 소재 | 금속성, 거칠기, 광택, 발광, 반투명 오버라이드 |
| 표현 | 표정 프리셋, 강도, 단축키, 자동 깜빡임과 립싱크 설정 |
| 물리 | 머리카락, 귀, 꼬리, 날개, 의상 계열별 강도와 감쇠 |
| 추적 | 보정 프로필 ID, 민감도, 흔들림 완화, 누락 시 복귀 시간 |
| 표현별 설정 | Inochi2D와 VRM에만 필요한 제한된 엔진별 오버라이드 |
| 권리 | 저장 시점에 사용된 자산 ID·버전·해시와 권리 스냅샷 |

공통 의미가 없는 엔진 내부 값은 `AvatarSpec`의 최상위 모델에 섞지 않는다. 엔진
어댑터의 제한된 오버라이드 영역에 둔다.

### 5.2 리그 계열

다음 리그 계열은 서로 별도로 정의한다.

- `Humanoid`: 사람
- `Kemonomimi`: 사람 골격에 동물 귀·꼬리·뿔·날개를 결합
- `AnthroBiped`: 주둥이, 발, 역관절 다리를 포함할 수 있는 이족 수인
- `Mascot`: 짧은 팔다리와 과장된 표정을 가진 캐릭터
- `Quadruped`: 고양이, 개, 여우, 토끼 등 사족 동물
- `Avian`: 날개와 부리를 주 동작 기관으로 사용하는 새 계열

리그 계열마다 필수 본·파라미터, 허용 슬롯, 표정 세트, 추적 리타게팅 규칙과
성능 예산을 선언한다. 사람형 자산을 사족형에 억지로 적용하지 않는다.

## 6. 자산 패키지

### 6.1 형식

Creator Studio 자산은 서명된 `.csavatarpack` 아카이브로 배포한다. 패키지는
다음을 포함한다.

- 패키지 매니페스트
- 2D 또는 3D 실제 소스와 런타임 자산
- 파츠 썸네일과 카탈로그 메타데이터
- 호환 리그·슬롯·의존성 선언
- 파일별 SHA-256
- Ed25519 공급자 서명과 서명 키 ID
- 라이선스 원문 또는 계약 증빙 참조
- 자동 검수 결과와 제작 도구 버전

압축 해제 경로 탈출, 중복 ID, 해시 불일치, 지원하지 않는 스키마, 순환 의존성,
성능 예산 초과를 설치 전에 거부한다. 실패 패키지는 격리하며 기존 설치본을
덮어쓰지 않는다.

### 6.2 권리 매니페스트

각 자산은 다음 권리를 `허용`, `금지`, `조건부`, `불명` 중 하나로 기록한다.

- 개인과 법인의 방송·녹화 수익화
- Creator Studio 설치본에 번들
- 색상·형태 변경과 파생 캐릭터 생성
- 완성 모델 파일 내보내기
- 원본 파츠 파일 재배포
- 프로젝트 휴대용 패키지에 포함
- 크레딧 의무
- 지역·기간·용도 제한

조합된 아바타의 권리는 사용 목적, 사용자 유형, 지역과 시점을 입력으로 받아 모든
사용 자산 권리의 교집합으로 계산한다. `AvatarSpec`의 권리 스냅샷은 감사 기록이며
출력 허가의 근거로 재사용하지 않는다. 방송·내보내기 시 설치된 매니페스트를 다시
해석한다. 내보내기 불가 파츠가 하나라도 포함되면 원본 모델 출력은 막고 제한을
일으킨 자산과 대체 가능한 자산을 표시한다.

외부 `.inx`, `.inp`, `.vrm`은 임베디드 이용 조건을 읽어 표시한다. 증빙이 없으면
`사용자 확인 필요`로 분류한다. 로컬 사용을 일괄 차단하지는 않지만, 앱이 해당
모델을 `상업 사용 확인됨`으로 인증하지 않는다.

### 6.3 출시 콘텐츠 기준

출시 카탈로그는 다음 최소 수준을 만족한다. 아래 수량은 2D와 3D 각각에 적용하며,
같은 의미 태그로 대응 자산을 찾을 수 있어야 한다.

- 각 지원 리그 계열마다 완성도 검수를 통과한 편집 가능 프리셋 3종 이상
- 현대 캐주얼, 판타지, 사이버, 포멀, 아이돌, 스트리트, 자연, 마스코트를
  포함한 8개 이상의 스타일 테마
- 레이어 조합 가능한 헤어 30종 이상
- 믹스 앤 매치 가능한 의상 세트 24종 이상
- 안경, 장신구, 모자, 뿔, 귀, 꼬리, 날개를 포함한 액세서리 50종 이상
- 밝은 피부·어두운 피부·털·비늘에서 모두 쓸 수 있는 색상과 패턴
- 2D와 3D에서 같은 의미 카테고리를 찾을 수 있는 카탈로그 태그

모든 파츠를 양쪽 엔진에서 픽셀 단위로 똑같이 만들 필요는 없다. 각 표현에서 같은
스타일 의도를 선택할 수 있어야 한다.

## 7. 커스터마이저 UX

### 7.1 작업공간

새 `Avatar` 작업공간을 추가한다.

- 중앙: 실제 2D 또는 3D 렌더 미리보기
- 왼쪽: 검색, 필터, 즐겨찾기, 최근 사용을 지원하는 파츠 카탈로그
- 오른쪽: 선택 파츠의 형태, 색상, 소재, 물리, 추적 설정
- 상단: 새 캐릭터, 불러오기, 저장, 실행 취소·재실행, 2D/3D 전환
- 하단: 웹캠 보정, 표정 테스트, 성능, 권리 상태

Android는 같은 기능을 하단 시트와 전체 화면 선택기로 재배치한다. 데이터와 기능을
줄이지 않고 화면 밀도만 바꾼다.

### 7.2 편집 기능

- 얼굴: 머리형, 얼굴 윤곽, 눈, 눈썹, 코, 입, 치아
- 체형: 키, 비율, 체격, 근육과 실루엣
- 스타일: 피부, 털, 비늘, 무늬, 메이크업, 흉터, 문신
- 헤어: 앞, 옆, 뒤, 묶음, 잔머리와 투톤·그라데이션
- 동물: 귀, 뿔, 부리, 주둥이, 갈기, 날개, 발, 꼬리
- 의상: 이너, 상의, 하의, 아우터, 신발, 장갑 레이어
- 소재: 색상, 금속성, 거칠기, 광택, 발광, 반투명
- 동작: 표정 세트, 단축키, 깜빡임, 립싱크, 호흡과 파츠 물리
- 편의: 비교, 팔레트 저장, 항목 잠금 랜덤 생성, 검색, 즐겨찾기

랜덤 생성은 호환 슬롯과 권리를 지키며, 사용자가 잠근 항목을 변경하지 않는다.
의상 관통이나 마스크 충돌을 감지하면 문제가 생긴 조합을 정확히 표시한다.

### 7.3 실시간 검사

- 웹캠 추적 테스트와 개인별 중립·최대 표정 보정
- 밝은 배경, 어두운 배경, 투명 배경 검사
- 360도 3D 회전과 2D 허용 각도 검사
- 실제 방송 축소 크기에서 얼굴과 실루엣 가독성 검사
- 현재 기기의 프레임 시간, 추적 시간, 메모리와 품질 단계 표시
- 변경 전후 비교와 저장 지점으로 복원

## 8. 2D Inochi2D 경로

기존 `Inochi2dModelRuntime`, `Inochi2dAvatarRenderer`,
`AvatarParameterMapper`, `AvatarRenderPipeline`을 폐기하지 않고 확장한다.

### 8.1 제작 규칙

2D 파츠는 임의 PNG가 아니라 호환 리그 계열에 맞춰 사전 리깅된 모듈이다. 모듈은
다음을 선언한다.

- 텍스처와 메시
- 레이어 순서와 마스크
- 디포머와 부모 슬롯
- 표정·머리·몸 파라미터
- 머리카락·귀·꼬리·의상 물리
- 색상 교체 채널
- 다른 파츠와의 가림·충돌 규칙

`2D AvatarCompiler`는 선택한 모듈을 검증하고 텍스처 아틀라스, 파라미터 매핑,
레이어와 마스크를 조합해 실제 런타임 모델을 만든다. 컴파일 결과는
`AvatarSpec + asset hashes + compiler version` 해시로 캐시한다.

### 8.2 품질 기준

- 눈 깜빡임, 시선, 모음 기반 입 모양, 미소·찡그림 등 기본 표정 완비
- 머리의 좌우·상하·기울기에서 레이어 찢김과 빈 공간이 없어야 함
- 머리카락, 귀, 꼬리, 의상의 물리 계열을 독립 조절
- 사람형 파라미터를 동물 얼굴에 단순 복사하지 않고 주둥이·귀·부리 표현으로 매핑
- 방송 축소 크기에서 선과 얼굴이 뭉개지지 않는 아틀라스 제공

전체 원화·리깅 제작 도구는 만들지 않는다. 승인된 모듈 조합과 세부 파라미터 편집에
집중한다.

## 9. 3D VRM·glTF 경로

3D는 휴머노이드 호환 캐릭터에 VRM 1.0을 사용한다. 마스코트, 사족, 조류처럼 VRM
휴머노이드 골격으로 표현할 수 없는 캐릭터에는 glTF 2.0과 Creator Studio 리그
메타데이터를 사용한다. 두 형식의 로더와 렌더러를 신규 어댑터로 추가하며, 외부
라이브러리 타입은 `cs_avatar`의 공통 인터페이스 밖으로 노출하지 않는다.

### 9.1 지원 기능

- 스킨드 메시와 본 애니메이션
- VRM 표정과 사용자 정의 모프
- MToon 계열 셀 셰이딩 소재
- 머리카락, 귀, 꼬리, 의상 보조 본 물리
- 모듈형 머리, 몸, 의상, 액세서리
- 사람형과 휴머노이드 호환 이족 수인은 VRM 골격
- 비휴머노이드 마스코트, 사족, 조류는 glTF 기반 Creator Studio 골격
- 데스크톱과 모바일 LOD, 텍스처 품질 단계

### 9.2 조합 규칙

의상과 몸은 호환 리그, 본 집합, 가림 마스크, 체형 범위를 선언한다. 컴파일러는
의상 아래 가려지는 몸 메시를 비활성화하고, 지원 범위를 벗어난 모프에서 관통이
발생하면 해당 조합을 경고한다. 자동 보정으로 품질을 숨길 수 없는 경우 사용자가
문제 파츠를 교체하도록 한다.

내보내기가 허용된 휴머노이드 조합은 VRM 이용 조건과 Creator Studio 권리
스냅샷을 함께 기록한 `.vrm`을 생성한다. VRM 휴머노이드 규격을 만족하지 않는
동물 조합은 권리가 허용될 때 `.glb`와 Creator Studio 리그 메타데이터를 함께
내보낸다. 비휴머노이드 모델을 VRM 호환이라고 잘못 표시하지 않는다. 허용되지 않은
원본 파츠를 우회 추출할 수 있는 출력은 제공하지 않는다.

## 10. 트래킹과 리타게팅

### 10.1 공급자

- 주 경로: 프로젝트 OSS 정책에서 승인된 MediaPipe 기반 얼굴·포즈·양손 추적
- 데스크톱 CPU 대체 경로: 기존 OpenSeeFace 별도 프로세스
- 카메라 실패 대체 경로: 마이크 오디오 립싱크와 절차적 대기 모션

모델 가중치와 제3자 고지는 라이브러리 코드와 별도로 해시·라이선스를 검수한다.
카메라와 마이크 데이터는 추적을 위해 외부 서버로 전송하지 않는다.

### 10.2 `AvatarMotionFrame`

공통 프레임은 다음 값을 타임스탬프와 신뢰도와 함께 가진다.

- 머리 위치와 회전
- 좌우 시선과 눈 깜빡임
- 입 열림과 모음 계열
- 눈썹, 볼, 미소, 찡그림 등 얼굴 표현
- 어깨, 팔꿈치, 손목과 상체 방향
- 좌우 손가락 관절과 제스처
- 오디오 음량과 발화 상태

현재 `ExpressionParameters` 기반 얼굴 경로는 호환 어댑터로 유지한다. 몸과 손을
기존 얼굴 구조에 억지로 추가하지 않고 초점이 분리된 값 객체로 확장한다.

### 10.3 리타게팅

- 사람형: 표준 얼굴, 상체, 손 동작으로 직접 매핑
- 케모미미: 사람형 동작에 귀·꼬리의 감정 보조 동작 추가
- 이족 수인: 주둥이와 역관절 다리 범위를 고려
- 마스코트: 작은 팔다리에 맞춰 이동량을 과장하거나 제한
- 사족: 사람 손 제스처를 앞발·날개·귀·꼬리 표현으로 선택 변환

신뢰도가 떨어지면 마지막 값을 고정하지 않는다. 설정된 시간 동안 감쇠해 중립
자세로 복귀하며, 얼굴이 사라지면 오디오 립싱크와 대기 모션으로 전환한다.

## 11. 렌더·저장·출력

### 11.1 동일 렌더 경로

`AvatarRenderPipeline`은 다음 소비자에게 같은 RGBA 프레임과 타임스탬프를 제공한다.

- Avatar 작업공간 미리보기
- 기존 `AvatarRenderCaptureSource`
- Studio 녹화와 편집 재생
- 방송 출력 어댑터

미리보기만 고품질이고 녹화 결과가 다른 문제를 막기 위해 렌더러를 복제하지 않는다.
해상도와 LOD는 소비자별로 다를 수 있지만 같은 모델, 모션, 소재 구현을 사용한다.

### 11.2 OBS 출력

방송 출력의 기본 계약은 프리멀티플라이드 알파를 포함한 타임스탬프 RGBA 프레임이다.
플랫폼에서 검증된 공유 프레임 경로가 있으면 알파 출력을 사용한다. 해당 경로를 쓸
수 없는 환경에는 단색 배경과 색상 충돌 검사를 갖춘 크로마키 출력 창을 제공한다.
OBS 코드나 GPL 구성요소를 닫힌 코어에 링크하거나 복사하지 않는다.

### 11.3 저장과 복구

- 편집 명령은 실행 취소·재실행 가능한 명령으로 기록한다.
- `AvatarSpec`은 변경 후 지연 자동 저장하며 마지막 정상본을 별도로 유지한다.
- 프로젝트에는 사용한 자산 ID, 버전, 해시와 권리 스냅샷을 저장한다.
- 자산이 없으면 임의 대체하지 않고 누락 목록과 설치·교체 선택지를 제공한다.
- 새 스키마는 이전 스키마를 명시적 마이그레이션한 뒤 저장한다.

## 12. 성능 기준

| 플랫폼 기준 | 출력 목표 | 지연 목표 |
|---|---|---|
| Windows, RTX 3060급 | 1080p 60fps | 모션 입력부터 미리보기까지 p95 80ms 이하 |
| macOS, Apple M1급 | 1080p 60fps | 모션 입력부터 미리보기까지 p95 80ms 이하 |
| Android, Snapdragon 8 Gen 1급 | 720p 30fps | 모션 입력부터 미리보기까지 p95 120ms 이하 |
| 상위 Android 기기 | 1080p 30fps | 모션 입력부터 미리보기까지 p95 120ms 이하 |

- 추론 주기와 렌더 주기를 분리하고 타임스탬프 기반으로 보간한다.
- 3D는 메시 LOD, 텍스처 크기, 물리 업데이트 빈도를 품질 단계로 관리한다.
- 2D는 아틀라스 해상도와 물리 업데이트 빈도를 품질 단계로 관리한다.
- 성능 단계 전환은 외형을 몰래 바꾸지 않고 사용자에게 현재 상태를 표시한다.
- 카메라, 추적, 렌더, 녹화 큐는 최신 프레임 우선 정책으로 지연 누적을 막는다.

오류 메시지는 내부 예외명만 보여주지 않고 사용자가 할 수 있는 다음 행동을 포함한다.

## 14. 검증 전략

### 14.1 자동 테스트

- `AvatarSpec` 생성, 직렬화, 스키마 마이그레이션과 잘못된 값 거부
- 자산 해시, 서명, 의존성, 경로 탈출, 중복 ID와 순환 의존성
- 권리 교집합과 내보내기 차단 원인
- 파츠 슬롯과 리그 호환성
- 2D 파라미터와 3D 본·표정 매핑
- 추적 보정, 흔들림 완화, 신뢰도 감쇠와 대체 경로
- 저장·재실행·누락 자산·충돌 복구
- 실제 `.inx`, `.inp`, `.vrm`, 비휴머노이드 `.glb` 샘플의 로딩 실패와 성공 경로
- 결정적 모션 입력에 대한 2D·3D 기준 이미지 비교
- 투명도, 색 공간, 프레임 타임스탬프와 녹화 동기

테스트용 모델만으로 출시를 승인하지 않는다. 상업 사용이 확인된 실제 출시 자산을
별도 수락 테스트에서 사용한다.

### 14.2 수동·실기기 검수

- 사람형과 동물형을 각각 2D와 3D로 새로 생성
- 얼굴·체형·헤어·의상·소재·동물 파츠를 세부 편집
- 웹캠 보정 후 얼굴·상체·손 추적
- 카메라 이탈과 재진입, 어두운 조명, 안경, 빠른 손동작
- 저장, 앱 종료, 재실행 후 동일 외형과 설정 복원
- Studio 녹화와 편집 재생의 외형·모션 일치
- 알파 또는 크로마키 방송 출력
- 허용 모델 내보내기와 제한 모델 차단
- Windows, macOS, Android의 모델 호환
- 키보드, 마우스, 터치, 고해상도 화면, 한국어와 영어 UI
- 밝은·어두운·복잡한 배경과 방송 축소 크기에서 가독성

### 14.3 장시간·성능 검수

- 각 기준 기기에서 2시간 연속 추적·렌더·녹화
- 메모리 증가, GPU 자원 누수, 오디오·비디오 동기, 누락 프레임 측정
- 품질 단계별 2D·3D 성능 예산 검증
- 앱 강제 종료 뒤 자동 저장 복구

## 15. 최종 출시 합격선

다음 조건이 모두 참이어야 기능 전체가 완료다.

1. 사람형과 동물형을 2D와 3D에서 실제 출시 자산으로 생성할 수 있다.
2. 승인된 모든 커스터마이징 범주가 저장·재실행 후 유지된다.
3. 얼굴·상체·손 추적과 오디오 대체 경로가 실제 카메라·마이크로 동작한다.
4. 미리보기, 녹화, 편집 재생, 방송 출력이 같은 렌더 결과를 사용한다.
5. 상업 사용 확인 자산에는 추적 가능한 계약 또는 라이선스 증빙이 있다.
6. 허용된 모델만 내보내며 제한 원인을 우회할 수 없다.
7. 승인된 기준 기기에서 프레임률, 지연, 2시간 안정성 목표를 통과한다.
8. 기본 카탈로그의 수량과 사람·동물·스타일 다양성 기준을 충족한다.
9. 사용자에게 노출되는 주요 경로에 정적 대체 화면이나 연결되지 않은 UI가 없다.

## 16. 구현 작업 분해

이 설계는 하나의 구현 계획으로 처리하기에 크다. 다음 독립 계획으로 나누되 공통
데이터 계약과 품질 기준은 이 문서를 따른다.

1. **Avatar Platform Foundation**
   - `AvatarSpec`, 리그·슬롯 값 객체, `.csavatarpack`, 카탈로그, 해시·서명,
     라이선스 해석, 저장·마이그레이션
2. **Production 2D Avatar Creator**
   - 모듈형 2D 자산 규약, 컴파일러, 기존 Inochi2D 런타임 확장, 실제 미리보기,
     2D 편집과 기준 이미지 테스트
3. **Production 3D Avatar Creator**
   - 휴머노이드 VRM 1.0과 비휴머노이드 glTF 로더, 셀 셰이딩 렌더러, 모듈
     메시·의상·모프·LOD, 실제 미리보기와 내보내기
4. **Animal Rig Families**
   - 케모미미, 이족 수인, 마스코트, 사족, 조류의 2D·3D 리그 규약과 파츠,
     표정·모션 리타게팅
5. **Full Motion Tracking and Retargeting**
   - MediaPipe 얼굴·포즈·손 공급자, 공통 모션 프레임, 보정, 감쇠, 오디오
     대체, 리그별 리타게팅
6. **Avatar Workspace and Output**
   - 데스크톱·Android 적응형 편집 UI, 실제 렌더 연결, Studio 녹화, 방송 출력,
     자동 저장과 복구
7. **Commercial Launch Content and Qualification**
   - 권리 확보 자산 제작·검수, 출시 카탈로그 수량 달성, 다국어·접근성,
     기준 기기 성능과 2시간 안정성 승인

각 계획은 테스트 가능한 실제 산출물을 내며, 후속 계획을 위한 빈 버튼이나 정적
아바타를 제품 완료로 표시하지 않는다.

## 17. 설계 결정 요약

- 2D와 3D를 별도 제품처럼 만들지 않고 공통 `AvatarSpec`과 편집 경험을 공유한다.
- 실제 렌더링은 Inochi2D와 VRM·glTF 전용 어댑터가 담당한다.
- 사람형과 동물형은 공통 카탈로그 안에서 별도 리그 계열로 관리한다.
- 기본 자산은 상업 권리를 확보한 것만 제공한다.
- 모델 내보내기는 조합된 모든 자산의 권리가 허용할 때만 가능하다.
- 데스크톱과 Android는 같은 모델·기능을 공유하고 UI와 품질 단계만 적응한다.
- 얼굴뿐 아니라 상체와 손을 추적하며 실패 시 오디오 립싱크와 대기 모션으로
  자연스럽게 전환한다.
- 목업, 테스트 패턴, 정적 미리보기는 출시 완료 증거로 인정하지 않는다.
